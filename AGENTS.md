## pCloud MCP — agent rules

- API quirks, token provenance, and endpoint limitations live in `docs/pcloud-notes.md`. Read it before asserting anything about pCloud behavior.
- Authentication: non-OAuth. `PCLOUD_ACCESS_TOKEN` is read from env and sent as `?access_token=` per the HTTP/JSON protocol. `PCLOUD_ACCESS_ID` is the application/access id, not a credential. `PCLOUD_API_SERVER` defaults to `eapi.pcloud.com` (EU). All requests hit `https://eapi.pcloud.com/<method>`; every response carries `result` (`0` = success, non-zero = error surfaced as MCP `isError`).
- 37 tools registered. The authoritative list, with titles, descriptions, and Zod input/output schemas, is `src/core/tools/index.ts` — that is the SSOT. `index.ts` must import each tool's `*InputSchema` from its handler file rather than re-declaring one inline, because the MCP SDK parses `tools/call` arguments against the registered schema and a Zod `.object()` strips unknown keys — an inline copy silently makes handler-only params unreachable over MCP. `deletefile` and `deletefolder` are intentionally separate. `resolve` wraps `stat` to give `{fileid|folderid, isfolder}`. `find` is a BFS over `listfolder` (pCloud exposes no documented search endpoint). `copyfile`/`copyfolder`/`downloadfile` are server-side (no bytes cross this server).
- Run `bun run typecheck && bun run build && bun test && bun run lint` after any change to `src/core/tools/*` or `src/mcp/*`.
- Regenerate mcporter artifacts after tool-surface changes (note: `mcporter generate-cli --server pcloud` writes `./pcloud.ts` at the repo root, which is gitignored): `mcporter generate-cli --server pcloud` + `bun build pcloud.ts --target=bun --outfile=generated/pcloud-cli.js --minify` + `mcporter emit-ts pcloud --mode types --out generated/pcloud-types.d.ts` + `mcporter emit-ts pcloud --mode client --out generated/pcloud-client.ts`. The generated files are gitignored and regenerated per-developer; the workspace-local skills at `.agents/skills/pcloud-{cli,client,types}/SKILL.md` must be updated to the new tool count.
- MCP registration is workspace-only via `.mcp.json` at the repo root (and `.kimi-code/mcp.json` locally, which is gitignored).
- Live verification: `bun run scripts/live-mcp-e2e.ts` (requires `PCLOUD_ACCESS_TOKEN`; creates a temp folder + file, exercises upload/getfilelink/deletefile/deletefolderrecursive, cleans up).
- Transport: stdio by default (`bun run dev`); HTTP via `MODE=http` on `127.0.0.1:3000` with a DNS-rebinding host allowlist, CORS deny-by-default, and a bearer gate for non-loopback binds. See `src/mcp/http.ts`.
- `uploadfile` and `uploadtolink` share `src/core/http/upload.ts` for chunked reads and progress; progress notifications echo the request's `_meta.progressToken` and are labeled `read`/`uploading`. `readfile` streams the download and cancels at `maxBytes`; the signed download URL is never returned.
- `extractarchive` runs server-side for ~2s; a `finished=false` response carries a `progresshash` that only the returned `hostname` can poll.
